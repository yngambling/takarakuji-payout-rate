# 宝くじ還元率ランキング

「どの宝くじが狙い目か一目で分かるサイト」。宝くじとスポーツくじの還元率を、キャリーオーバー込みで1日5回自動計算して公開する静的サイトです。
サーバーは不要で、GitHub Actions が公式サイトからデータを取り、ページを作り直して公開します。

## できること

- 今日の還元率：結論ボックス（今日の狙い目・締切までのカウントダウン・ポイント込みの還元率）、王冠つきのTOP3、全くじのランキング（還元率・ポイント込み・キャリーオーバー・1等の金額と確率・次の回・全購入場所へのボタン）、ポイントでお得に買う方法（登録・口座開設・カードの案内）、等級ごとの当せん金と確率、最近の結果、よくある質問
- ポイント還元ランキング：購入場所ごとのポイント還元率（内訳つき）、くじ別の「ポイント込みの還元率」（毎日計算）、ポイントの組み合わせ方、宝くじ公式サイトで使えるカードと月の上限、よくある質問、出典
- くじ別ページ：還元率のスコアボード（前日比・ポイント込み）、購入ボタン（上と下の2か所）、購入場所（ポイントが多い順・口座開設やカードのボタンつき）、等級表、キャリーオーバーの額ごとの還元率、最近の結果、還元率の推移（過去1年）
- 宝くじ一覧（くじごとのしくみ）、購入場所（比較表・目的別のおすすめ・ネットで買う3ステップ・ネット以外の購入場所）、還元率の推移（直近1か月のグラフと表）、計算方法
- 宝くじの基礎知識（解説ページ）：還元率・期待値とは（くじ別の一覧）、当選確率の比較、当せん金と税金、当せん金の受け取り方、ネットで買う方法。表や数字の一部は毎日の計算から自動で入る
- 全ページ共通：キャリーオーバー速報の帯（はみ出すときは横に流れる）、右サイドバー（TOP5・キャリーオーバー・ポイント還元TOP3・くじ別）、目次、シェアボタン、パンくず、スマホで画面の下に出る購入ボタン
- 動き：数字のカウントアップ、還元率のバー、グラフの線、スクロールで表示、ボタンの光。OSの「視差効果を減らす」がオンの人には動きを止めます
- 収益化の枠：Google AdSense（本文に最大4か所＋サイドバー・ads.txt 自動生成）、アフィリエイトリンク（「PR」表記と rel="sponsored" を自動付与）、登録・口座開設・カードの申し込みボタン
- プライバシーポリシー（Cookie・外部送信）、運営者情報（ランキングの決め方・情報の確認日）、sitemap.xml、robots.txt、OGP画像、構造化データ（パンくず・よくある質問）

外部のパッケージは使っていません（Node.js 20 以上だけで動きます）。

## 公開までの手順（30分ほど）

### 1. GitHub にリポジトリを作る

1. GitHub のアカウントを作り、新しいリポジトリを **Public** で作ります（Public なら Actions も Pages も無料）。
2. このフォルダの中身をすべてアップロードします。ブラウザなら「Add file → Upload files」に、フォルダごとドラッグして入れられます。`.github` フォルダも必ず含めてください（隠しフォルダなので、見えない場合は表示設定をオンにします）。

### 2. 自動更新を有効にする

1. リポジトリの **Settings → Actions → General → Workflow permissions** で「Read and write permissions」を選んで保存します。
2. **Settings → Pages → Build and deployment → Source** を「GitHub Actions」にします。
3. **Actions** タブで「還元率を更新して公開」を開き、「Run workflow」を押します。2〜3分で `https://ユーザー名.github.io/リポジトリ名/` に公開されます。
4. 実行結果のページ（Summary）に、取得できたキャリーオーバーなどが一覧で出ます。⚠ が出ていたら下の「取得に失敗したとき」を見てください。
5. 通知を受け取れるようにします（下の「問題が起きたときのお知らせ」）。

以後は日本時間の 7:47・12:47・19:47・21:47・23:47 に自動で更新されます。ただし GitHub の予約だけだと数時間遅れることがあるので、下の「定時更新を時刻どおりに動かす（外部タイマー）」も設定してください。

公開した直後は、くじ別ページの「過去1年」のグラフが短い線になります。毎回の更新で公式データを少しずつ（1回に最大12件）さかのぼって集めるので、数日で1年分そろいます。急ぐときは、リポジトリの **Settings → Secrets and variables → Actions → Variables** で `BACKFILL_PER_RUN` という変数を作り、40 などの大きな数を入れます。

#### 定時更新を時刻どおりに動かす（外部タイマー）

2026年8月ごろから、GitHub の予約実行（schedule）は数時間遅れたり、抜けたりすることがあります（GitHub 側の不具合で、手動の実行はすぐ動きます）。そこで、無料の外部サービス **cron-job.org** から、決まった時刻に GitHub へ「実行して」と頼みます。Actions タブで「Run workflow」を押すのと同じ仕組みです。GitHub の予約も、外部タイマーが止まったときの予備として同じ時刻に残しています。

**1. GitHub でトークン（合い鍵）を作る**

1. [トークンの作成画面（入力済み）](https://github.com/settings/personal-access-tokens/new?name=cron-job.org+takarakuji+update&description=Run+update.yml+from+cron-job.org&expires_in=366&actions=write) を開きます。名前・期限（366日）・権限（Actions の Read and write）が入った状態で開きます。
2. **Repository access** で **Only select repositories** を選び、**Select repositories** で `takarakuji-payout-rate` を選びます。
3. **Permissions** に **Actions**（Read and write）と **Metadata**（Read-only）だけがあることを確認します。
4. 一番下の **Generate token** を押し、表示された `github_pat_` で始まる文字列をコピーします（画面を閉じると二度と表示されません。分からなくなったら作り直します）。

このトークンでできるのは、このリポジトリの自動更新（Actions）の操作だけです。コードやサイトの中身は書き換えられません。

**2. cron-job.org に予約を作る**

1. [cron-job.org の登録ページ](https://console.cron-job.org/signup) で、First name・Last name・Email address・Password・Password (repeat) を入れ、2つの同意（Terms of Service・Privacy Policy）にチェックして **CREATE ACCOUNT** を押します。届いたメールのリンクで有効にしてから、[ログインページ](https://console.cron-job.org/login) で **SIGN IN** します。
2. 左のメニューの **Cronjobs** を開き、**CREATE CRONJOB** を押します（メニューが閉じているときは、左上の ☰ を押すと開きます）。
3. **COMMON** タブの **Title** に `宝くじ還元率の定時更新` と入れます。**URL** 欄にはじめから入っている `http://` を消し、次の1行をそのまま貼り付けます（`YOUR_TOKEN` はこの時点ではそのまま）。

   ```
   47 7,12,19,21,23 * * * curl -X POST -H "Accept: application/vnd.github+json" -H "Authorization: Bearer YOUR_TOKEN" -H "X-GitHub-Api-Version: 2022-11-28" -H "Content-Type: application/json" -d '{"ref":"main"}' https://api.github.com/repos/yngambling/takarakuji-payout-rate/actions/workflows/update.yml/dispatches
   ```

   「This looks like a crontab line」と出たら、**IMPORT COMMAND** を押します。画面の下に「Imported: URL, request method, 4 headers, request body, execution schedule.」と出れば、URL・送り方（POST）・ヘッダー4つ・本文・実行時刻がまとめて入っています。
4. **ADVANCED** タブを開きます。
   - **Headers** の `Authorization` の **Value** を消し、`Bearer `（Bearer と半角スペース）に続けて、1でコピーしたトークンを貼り付けます。
   - **Time zone** が `Asia/Tokyo` になっていることを確認します（違っていたら選び直します）。
   - **Request method** が `POST`、**Request body** が `{"ref":"main"}` になっていることを確認します。
5. **NOTIFICATIONS** タブで、**execution of the cronjob fails**・**execution of the cronjob succeeds after it failed before**・**the cronjob will be disabled because of too many failures** の3つをオンにします。失敗したとき（トークンの期限切れなど）にメールが届きます。
6. **COMMON** タブに戻り、**Execution schedule** の下に次の実行予定が5つ（「12:47 PM」「7:47 PM」のように午前・午後で表示。7:47・12:47・19:47・21:47・23:47 のどれか）と、「In this job's individual timezone (Asia/Tokyo).」が出ていることを確認します。
7. 下の **TEST RUN** → **START TEST RUN** を押します。結果に **204** と出れば成功で、GitHub の Actions タブに「workflow_dispatch」の実行が1つ増えます（401・403・404 と出たら、トークンの貼り付け、トークンで選んだリポジトリ、URL のどれかが違っています）。
8. **CREATE** を押して保存します。

**トークンの期限（1年）が近づいたら**：期限の30日前に「外部タイマーのトークンの期限が近づいています」という Issue が届きます（期限は `config/site.json` の `timerTokenExpires`。いまは 2027-10-13）。上の1と同じ手順で新しいトークンを作り、cron-job.org の **Cronjobs** でこのジョブの **EDIT** を押し、**ADVANCED** タブの `Authorization` を `Bearer 新しいトークン` に書き換えて **SAVE** を押します。`timerTokenExpires` を新しい期限に書き換えると、Issue は自動で閉じます。古いトークンは GitHub の **Settings → Developer settings → Personal access tokens → Fine-grained tokens** で削除します。期限が切れたままでも、更新は GitHub の予約（遅れることがある）で続きます。外部タイマーからの実行が13時間以上来ないときも、Issue でお知らせします。

### 3. 自分の情報に書き換える

`config/site.json` を開いて、次を書き換えて保存（コミット）します。保存すると自動でサイトが作り直されます。

- `baseUrl`：公開したURL（独自ドメインにしたらそのURL。末尾の / は不要）
- `operatorName`：運営者名（ハンドルネームで可）
- `contactEmail` か `contactFormUrl`：問い合わせ先（任意）。設定したときだけ「このサイトについて」にお問い合わせ欄が出ます。AdSense やASPの審査では運営者に連絡できるかを見られることがあるので、Googleフォームで作ったフォームのURLを入れておくと安心です
- `xAccount`：X のアカウント名（任意）

### 4. 独自ドメインにする（AdSense を使うなら必要）

AdSense は、自分が管理するドメインで申請するのが確実です（`github.io` のままでは審査に通りにくいとされています）。

1. ドメインを取得します（.com で年1,000〜2,000円程度）。
2. **Settings → Pages → Custom domain** にドメインを入れ、表示された内容どおりにドメイン側の DNS を設定します。
3. 「Enforce HTTPS」にチェックを入れます。
4. `config/site.json` の `baseUrl` をそのドメインに変えます。

このサイトは `https://takarakuji-kangen.com`（2026年10月11日に Xserverドメインで取得）で公開しています。古い `https://yngambling.github.io/takarakuji-payout-rate/` は、新しいドメインに自動で転送されます。Xserverドメインの「DNSレコード設定」には、次を登録しています（元からある NS と SOA の行は消さないでください）。

#### GitHub Pages の利用条件について

GitHub Pages は「オンラインビジネスや商取引を主な目的とするサイト」の無料ホスティングとしての利用を認めていません。広告付きの情報サイトは一般に問題になりにくいものの、アフィリエイト中心の運営に不安があれば、商用利用できる **Cloudflare Pages**（無料プランは月500回までビルド可）で公開する方法もあります。

1. Cloudflare の「Workers & Pages → Pages → Git に接続」でこのリポジトリを選びます。
2. ビルドコマンドに `node scripts/build.mjs`、出力ディレクトリに `dist` を指定し、環境変数 `NODE_VERSION` に `22` を入れます。
3. GitHub のリポジトリの **Settings → Secrets and variables → Actions → Variables** で、`DEPLOY_TARGET` という変数に `cloudflare` を入れます（GitHub Pages への公開が止まり、データの取得と保存だけを Actions が行います）。

## 収益化

### A. アフィリエイト（審査は案件ごと。すぐ始められる）

1. ASP に登録します：A8.net、もしもアフィリエイト、バリューコマース、afb、アクセストレード、楽天アフィリエイトなど。サイトのURLを登録するので、先に公開しておきます。
2. ASP の管理画面で、次の案件を探して提携を申し込みます。サイトにはすでに、それぞれのボタンの枠があります。

   | 枠（links.json） | 案件の例 | どこに出るか |
   |---|---|---|
   | `signups.paypay_card` | PayPayカード | 宝くじ公式サイト×PayPayクレジット（ポイント2.0%）の案内 |
   | `signups.rakuten_card` | 楽天カード | 楽天toto×楽天カード（ポイント2.0%）の案内 |
   | `signups.d_card` | dカード | ドコモスポーツくじ×dカード（ポイント2.0%）の案内 |
   | `signups.rakuten_bank` ほか | 楽天銀行・PayPay銀行・auじぶん銀行・ドコモSMTBネット銀行の口座開設 | 銀行の購入場所の「口座を開く」ボタン |
   | `shops.*` | 楽天toto など、くじの販売サイトそのもの | すべての購入ボタン |

   報酬の目安：A8.net の解説（2026年5月更新）では、クレジットカードは1件500〜5,000円（審査がやさしいカードは500〜1,500円、ゴールドカードなどは4,000〜5,000円）です。銀行の口座開設は数百円〜千円台の案件が多く、カードより低いことが一般的です。一方で、このサイトの読者は「くじを買うために口座やカードが必要」なので、申し込みにつながりやすいと考えられます。いま募集中の案件と報酬額は、各ASPの管理画面でしか確認できません。

   案件ごとに「ギャンブル関連サイトへの掲載不可」などの条件があることがあります。申し込む前に掲載条件を確認してください。宝くじ公式サイトとスポーツくじ公式サイト自体のアフィリエイトは見つかりませんでした。
3. 提携できたら `config/links.json` で、その枠の `url` を広告リンクに差し替え、`"affiliate": true` にします。「PR」表記と `rel="sponsored"` が自動で付きます。
4. ボタンの並び順はポイントの率で決まり、広告かどうかでは変わりません（「このサイトについて」にもそう書いています）。順番を広告で変えると、比較の信頼性が下がり、景品表示法の観点でも問題になりやすいためです。

### B. Google AdSense（審査あり）

審査に必要なページ（運営者情報・お問い合わせ・プライバシーポリシー（広告の Cookie の説明つき）・免責事項）と、ページごとの本文はそろっています（2026年10月12日に全26ページを点検：本文は約2,000〜10,000字、リンク切れなし）。

1. [Google AdSense](https://adsense.google.com/) に、Search Console と同じ Google アカウントで登録します（18歳以上・支払いの受け取り先の情報が必要です）。
2. AdSense の **アカウント** → **設定** → **アカウント情報** に出る **サイト運営者 ID**（パブリッシャー ID。`pub-` から始まる16桁の数字）を確かめ、`config/site.json` の `adsense.client` に `ca-pub-1234567890123456` の形で入れて保存します（Claude に ID を伝えて頼んでもかまいません。この ID は ads.txt やページのコードで誰でも見られるもので、秘密ではありません）。保存すると、数分で全ページに審査用のメタタグと AdSense のコード、`ads.txt` が出ます。広告そのものは、審査に通るまで出ません。
3. AdSense の **サイト** → **＋ 新しいサイト** で `takarakuji-kangen.com` を入れて **保存** します。
4. 所有権の確認の方法は **メタタグ**（または **AdSense コード スニペット**）を選び、「…を貼り付けました」などのチェックを入れて **確認** を押します（2の保存のあと、公開が終わってから押します）。
5. **審査をリクエスト** を押します。同意管理プラットフォーム（CMP）の選択が出たら、Google の CMP を選ぶのがおすすめです（ヨーロッパなどの読者にだけ同意の画面が出て、日本の読者には出ません）。審査は数日、長いと2〜4週間かかります。
6. 審査に通ったら、AdSense の **広告 → サイトごと** で自動広告をオンにするか、広告ユニットを作って `adsense.slots`（top・middle・middle2・bottom・sidebar）にIDを入れます。
7. 通らなかったときは、理由（「有用性の低いコンテンツ」など）を Claude に見せてください。直してから、もう一度 **審査をリクエスト** を押します。

Google のポリシー（パブリッシャー向け制限コンテンツ）では、オンラインの宝くじやスポーツくじの販売と、そのページへ誘導するアフィリエイトサイトは「オンライン ギャンブル」として広告が制限される対象です。ただし、日本のユーザーに配信する場合は除外される国に含まれています（2026年10月12日に確認）。広告の出やすさは審査後の実績で判断してください。

### C. アクセスを集める

- Google Search Console にサイトを登録し、`sitemap.xml` を送信します（下の「Google Search Console に登録する」）。その後の見張りは「Search Console の自動チェック」で自動にできます。
- キャリーオーバーが大きく増えた日や、還元率の順位が入れ替わった日に、各ページの「Xでポスト」ボタンから投稿すると、見に来る理由になります。X への自動投稿は X の API が有料（2026年10月時点で従量課金。リンク付きの投稿は1件0.2ドル）のため、入れていません。

### Google Search Console に登録する

検索結果への表示状況が分かり、Google にページを早く見つけてもらえます。

独自ドメイン（`takarakuji-kangen.com`）は「ドメイン」プロパティで登録します。

1. [Google Search Console](https://search.google.com/search-console) を開き、左上のプロパティ名の右の「▼」から「プロパティを追加」を押します（初めてなら「今すぐ開始」）。
2. プロパティ タイプは左側の「ドメイン」を選び、`takarakuji-kangen.com` を入れて「続行」を押します。
3. 表示された TXT レコード（`google-site-verification=` から始まる文字）を「コピー」します。
4. XServerアカウントの「DNSレコード設定」で、ホストは空欄、種別は「TXT」、内容にコピーした文字を貼って追加します。TTL と優先度はそのままです。
5. Search Console に戻って「確認」を押します。失敗したら、しばらく待ってからもう一度押します（DNS の反映には最大24時間かかります）。
6. 左のメニューの「サイトマップ」を開き、「新しいサイトマップの追加」に `https://takarakuji-kangen.com/sitemap.xml` と入れて「送信」を押します。

`robots.txt`（`https://takarakuji-kangen.com/robots.txt`）にもサイトマップの場所を書いているので、Google 以外の検索エンジンもサイトマップを見つけられます。`config/google-site-verification.txt` のタグは、独自ドメインに移る前に `github.io` の URL で登録したときのものです。残しておいても問題ありません。

サイトマップの `lastmod`（最終更新日）は、ページの本文が実際に変わった日です（`data/pages.json` に記録。更新時刻やサイドバーだけの違いは数えません）。「このサイトについて」のように変わらないページは、古い日付のままになります。

Bing Webmaster Tools には、Search Console からの取り込みで登録しています（2026年10月12日）。

### Search Console の自動チェック（任意・最初に15分ほどの設定）

設定すると、毎朝の見張りで次のことを自動で行います。Search Console の画面を開いて確かめる必要がなくなります。

- サイトマップが送信されているか・エラーがないかを確かめます。送信されていなければ送り、7日以上読み込まれていなければ送り直します。
- サイトマップの全ページを「URL 検査」で調べ、Google に登録（インデックス）できているかを数えます（Actions の実行結果の Summary に「Google に登録済み 〇/〇ページ」と出ます）。
- robots.txt・noindex・404・サーバーエラーなど、**直す必要がある理由で登録できないページ**があれば Issue で知らせます。新しいサイトでよくある「まだ登録されていない」だけのページは知らせません。
- 「インデックス登録をリクエスト」は Google の API でできないため、急ぐページがあるときだけ、今までどおり画面から押します。検索での表示回数やクリック数は、公開リポジトリに残さないため取得しません。

設定のしかた（Google のアカウントは、Search Console に登録したものを使います）：

1. [Google Cloud の新しいプロジェクトの作成](https://console.cloud.google.com/projectcreate) を開き、プロジェクト名に `takarakuji-kangen` と入れて **作成** を押します（初めて開くと利用規約の画面が出るので、国に「日本」を選んで同意します。Search Console API は無料で、支払い情報の登録はいりません。無料トライアルの案内が出ても申し込む必要はありません）。
2. [Google Search Console API](https://console.cloud.google.com/apis/library/searchconsole.googleapis.com) を開き、上で作ったプロジェクトが選ばれていることを確かめて **有効にする** を押します。
3. [サービス アカウントの作成](https://console.cloud.google.com/iam-admin/serviceaccounts/create) を開き、サービス アカウント名に `search-console-check` と入れて **完了** を押します（ロールは付けません）。
4. 一覧に出たサービス アカウントのメールアドレス（`search-console-check@….iam.gserviceaccount.com`）をコピーしておきます。続けてそのメールアドレスを押し、**キー** タブ → **鍵を追加** → **新しい鍵を作成** → **JSON** → **作成** を押します。JSON のファイルがダウンロードされます（合い鍵なので、人に渡したりチャットに貼ったりしないでください）。
5. [Search Console](https://search.google.com/search-console) で `takarakuji-kangen.com` を開き、**設定** → **ユーザーと権限** → **ユーザーを追加** を押し、4でコピーしたメールアドレスを入れ、権限を **フル** にして **追加** を押します（サイトマップの送信には「フル」が必要です）。
6. GitHub のリポジトリの **Settings → Secrets and variables → Actions** を開き、**New repository secret** を押します。**Name** に `GSC_CREDENTIALS`、**Secret** にダウンロードした JSON ファイルの中身をすべて（`{` から `}` まで）貼り付けて **Add secret** を押します。貼り付けたら、パソコンの JSON ファイルは消してかまいません。
7. 次の朝の更新から動きます。すぐ試すときは、**Actions** タブの「Run workflow」で「公式ページの見張りも今すぐ行う」にチェックを入れて実行し、Summary に「Search Console：Google に登録済み 〇/〇ページ」と出るか確認します。

プロパティは「ドメイン」（`sc-domain:takarakuji-kangen.com`）として扱います。URL プレフィックスのプロパティを使うときは、`config/site.json` に `"searchConsoleSite": "https://takarakuji-kangen.com/"` を足します。止めたいときは、GitHub の Secrets から `GSC_CREDENTIALS` を消します。

### 検索エンジン（Bing など）に更新を知らせる（IndexNow）

IndexNow は、内容が変わったページを検索エンジンにすぐ知らせる仕組みです。送ると、Bing・Yandex・Naver・Seznam など IndexNow に参加している検索エンジンに共有されます（Google は参加していないので、Google は今までどおりサイトマップで見つけます）。

- **送るタイミング**：1日1回、日本時間の朝6時以降の最初の更新（ふだんは7:47）で、前の日に送ったあとで本文が変わったページだけを選び、公開が終わってから送ります（`scripts/indexnow.mjs`）。同じページを1日に何度も送らないため、IndexNow の推奨に沿っています。
- **キー**：`config/site.json` の `indexNowKey`（英数字32文字）です。サイトの一番上に `キー.txt` というファイルを自動で置き、検索エンジンはそれでこのサイトからの通知だと確かめます。キーは公開される前提のもので、秘密にする必要はありません。
- **結果の確認**：Actions の実行結果（Summary）の「検索エンジンへの通知（IndexNow）」に、送った件数と結果が出ます。Bing Webmaster Tools の「IndexNow」でも、受け取ったURLを確認できます。
- **止めたいとき**：`indexNowKey` を空（`""`）にします。キーを変えたいときは、新しい英数字32文字に書き換えます（古いキーのファイルは次の公開で消えます）。

### サイトに取り入れたアフィリエイトサイトの作り方

- 独自の数値で比べる：Google は、商品説明を写しただけのページを「価値の低いアフィリエイト」とし、価格などの追加情報・独自の評価・比較のあるサイトは価値があるとしています。このサイトは還元率とポイント込みの還元率を毎日自分で計算しています。
- 根拠を示して順位を付ける：ランキングは還元率とポイントの率の数値順で、出典と確認日を載せています（A8.net も、比較は客観的な数値で公正に行うよう求めています）。
- 複数の購入先を並べる：Google のレビューの指針どおり、読者が好きな購入先を選べるようにしています。
- 判断する場所のすぐ近くにボタンを置く：結論ボックス・TOP3・比較表・くじ別ページの上下・スマホの追従ボタン。ボタンの下に安心材料（スマホで1口から・照合は自動）を書いています。
- 広告であることを分かりやすく：リンクごとに「PR」を付け、全ページ上部にも表示しています（消費者庁のQ&Aでは、冒頭の一文だけでは足りない場合があるとされています）。
- 情報を新しく保つ：ポイントの条件が変わったら `config/points.json` を直します（ASPは提携内容の変更に約1週間以内での修正を求めることがあります）。

### 表示のルール

- アフィリエイトのリンクには「PR」が自動で付きます。全ページの上にも広告を含む旨を表示しています（景品表示法のステルスマーケティング規制への対応）。
- スポーツくじは19歳未満は購入できない旨をフッターに表示しています。
- 「必ず当たる」「一番儲かる」のような表現は使わないでください（ASPの禁止表現にあたります）。
- 海外のオンラインカジノへの誘導は法律で禁止されています。カジノ系のアフィリエイトは載せないでください。

## 問題が起きたときのお知らせ（自動チェック）

サイトは、確認が必要なことを自動で見つけて、GitHub の **Issue**（課題の一覧）に書き込みます。Issue には運営者あての @メンションが付くので、GitHub から**メールで通知**が届きます。Issue には「何が起きたか」「どのファイルを直すか」「直し方」が書いてあります。

| 毎回（1日5回） | ロトの結果が長く入ってこない（取得はできているのに更新が止まっている） | 新しい結果が入ったら自動で閉じる |
| 毎回（1日5回） | 自動更新そのものが途中で止まった・サイトの公開（GitHub Pages）に失敗した | 次の更新・公開が成功したら自動で閉じる |

公式ページの見張りは1日1回だけです（同じ日の2回目からの更新では行いません）。今すぐ見張りもやり直したいときは、Actions タブの「Run workflow」で「公式ページの見張りも今すぐ行う」にチェックを入れてから実行します。外部タイマー（cron-job.org）からの呼び出しが失敗したときは、cron-job.org からメールが届きます。

同じ問題が続いても、Issue は1つだけです（毎回メールが届くことはありません）。

### 通知を受け取る設定

1. GitHub の右上のアイコン → **Settings → Notifications** を開きます。
2. 「Subscriptions」の **Participating, @mentions and custom** で **Email** にチェックが入っていることを確認します（入っていなければ入れます）。
3. リポジトリの **Settings → General → Features** で **Issues** にチェックが入っていることを確認します（最初から入っています）。
4. 確認のため、**Actions** タブから「Run workflow」を押してもかまいません。問題がなければ Issue は作られません。

自動更新そのものがエラーで止まったときは、GitHub からも「Run failed」のメールが届きます（ワークフローを最初に作った人あて）。

### 数値を自動で書き換えるもの・書き換えないもの

ポイントの率やくじのルール（賞金・確率・配分・上限）は、公式ページの書き方が会社ごと・ページごとに違うため、プログラムで読み取ると、違う数字を載せてしまうおそれがあります。違う率や賞金を載せると、読者に誤解を与え、景品表示法の面でも問題になりかねません。そのため、変化を見つけて知らせるところまでを自動にし、数値は確認してから直す形にしています。

例外は**新しいジャンボ宝くじ**です。宝くじ公式サイトの発表（宝ニュース）は毎回同じ形の賞金表なので、読み取った数字を次のように検算し、**すべて通ったときだけ**自動で載せます（1つでも合わなければ載せずに Issue で知らせます）。2025〜2026年の発表10回分（バレンタイン・ドリーム・サマー・年末・ハロウィンとそれぞれのミニ）は、すべて正しく読み取れることを確かめています。

- 発売総数を「発売総額÷1枚の値段」「ユニット数×1ユニットの枚数」「いちばん安い賞の本数×10」のうち2つ以上で出して、一致する
- 賞金の合計が発売総額の40〜50%（法律で5割まで）
- 1等・2等…の番号が抜けていない、読めない行がない、1等の本数がユニット数で割り切れる、前後賞は1等の2倍、組違い賞は1等×（組の数−1）
- 発売期間・抽せん日の順番が正しく、まだ売り終わっていない

自動で載せたジャンボのページには「賞金・本数・発売期間は、〇年〇月〇日の宝くじ公式サイトの発表から自動で読み取ったものです（運営者の確認待ち）」と出し、Issue で公式発表との見比べをお願いします。

### 修正も自動に近づけたいとき（任意・有料）

Anthropic の **Claude Code GitHub Actions** を入れると、Issue に「@claude この内容で直して」とコメントするだけで、Claude が修正案を作り、プルリクエスト（変更の提案）として出してくれます。内容を見て「Merge」を押せば反映されます。Claude の GitHub アプリのインストールと、Claude の API キー（使った分だけ料金）または Claude のサブスクリプション用のトークンの登録が必要です。くわしくは [Claude Code GitHub Actions の説明](https://code.claude.com/docs/en/github-actions) を見てください。

### 自動になっていること・人が判断すること

| 作業 | 自動？ | 人がすること |
|---|---|---|
| キャリーオーバー・販売額・結果の取得、還元率の計算、サイトの生成と公開（1日5回） | 自動 | なし |
| 新しいジャンボ宝くじの登録（賞金表・ページ・解説・購入先） | 自動（検算に通ったものだけ） | Issue を見て、公式発表と同じなら閉じる |

| GitHub Actions の部品の更新 | 自動（プルリクエストを作る） | 「変更の確認」に ✓ が付いていればマージ |
| 証明書・ドメイン・外部タイマーのトークンの期限 | 自動（近づいたら知らせる） | ドメインの更新（自動更新の設定）とトークンの作り直し（年1回） |
| アフィリエイトの提携・AdSense の申請 | — | 各社の審査があるので、申し込みとリンクの差し替えは人が行う |

ポイントの率やくじのルールを自動で書き換えないのは、読み違えた数字を載せると読者の誤解や景品表示法の問題につながるためです（「数値を自動で書き換えるもの・書き換えないもの」）。直すときは、Issue を Claude に見せて「直して」と頼めば、修正のプルリクエストを作ります。

### プルリクエストの確認と、部品の自動更新

- プルリクエスト（変更の提案）を出すと、「変更の確認」（`.github/workflows/check.yml`）が計算の確認とサイトの生成を試し、緑の ✓ か赤い × を付けます。✓ ならマージしても自動更新は止まりません。
- GitHub Actions の部品（`actions/checkout` など）に新しい版が出ると、Dependabot が更新のプルリクエストを月1回まで、1つにまとめて作ります（`.github/dependabot.yml`）。✓ が付いていればマージしてかまいません。
- マージしたブランチを自動で消すには、リポジトリの **Settings → General** の **Pull Requests** にある **Automatically delete head branches** にチェックを入れます。

### ポイントの率が変わったとき

`config/points.json` の `parts` の `rate`（0.01 = 1%）と `checkedOn`（確認日）を直します。期間限定の上乗せは `campaigns` に書きます。`until` の日付を過ぎると自動で表示されなくなります。

```json
{ "campaigns": [ { "route": "rakuten_toto", "rate": 0.01, "title": "楽天totoのBIG購入でポイント＋1%", "until": "2026-11-30", "url": "https://..." } ] }
```

ポイントの情報は 2026年10月10日に各社の公式ページで確認したものです。宝くじ公式サイト×PayPayクレジットの2.0%は、宝くじポイント（公式）1%に、PayPayが公表している基本付与率1.0%を足したもので、PayPay側の率は宝くじ専用の記載ではありません。

### BIG777（毎月7日を含む週の BIG）

BIG は、毎月7日を含む週の回だけ、1等の上限がキャリーオーバーの有無にかかわらず **7億7万7千円** に上がります（日本スポーツ振興センターの「BIG777」。通常は3億円、キャリーオーバー発生時6億円）。キャリーオーバーが多いときは、還元率が約7ポイント上がります。

公式の発表は「毎月7日を含む週」までで、どの回が対象かは細かく書かれていません。このサイトは、これまでの1等の当せん金（7億7万7千円と6億円ちょうど）と合う、次の決め方で自動で判定します。

- 毎月7日を含む週（**日曜〜土曜**）に販売が終わる回のうち、**最後に販売が終わる回**
- 1等の当せん者が出た回は、実際の当せん金で決めます（6億円を超えていれば BIG777、6億円ちょうどなら通常の回）
- 週の途中（日〜木曜）に締め切る回は、同じ週にあとから締め切る回があるか分かるまで、通常の回として計算します

BIG777 の回は、トップページとくじ別ページに「BIG777」の印とお知らせが出て、還元率も上限7億7万7千円で計算します。設定は `data/games.json` の `big` の `special` にあります。

**毎月のお知らせ**：BIG777 の回が分かると、「【お知らせ】今月の BIG777 は第○回として計算しています」という Issue が届きます。BIG を売っているサイトで、1等の最高額が「7億7万7千円」になっている回と同じか確認してください。合っていれば何もしなくてかまいません（週が終わって1週間で自動で閉じます）。

**判定が違っていたとき**：`data/overrides.json` の `big777` を直します。BIG777 の回の番号を `add` に、BIG777 ではない回の番号を `remove` に入れます。たとえば、本当は第1671回が BIG777 で、サイトが第1670回を BIG777 にしていたら、次のようにします。

```json
 "big777": {
  "_how": "（説明の文。そのまま残します）",
  "add": [1671],
  "remove": [1670]
 }
```

### 取得に失敗したとき

公式サイトの作りが変わると、取得に失敗することがあります。失敗した項目は前回の値のまま表示され、くじ別ページに注意書きが出ます。

1. Actions の実行結果（Summary）で、どのくじが失敗したかを確認します。
2. 手元で `node scripts/fetch.mjs --dump` を実行すると、取得した生データが `debug/` に保存されます。これを見てパーサー（`scripts/lib/parse.mjs`）を直します。
3. 急ぐときは `data/overrides.json` に値を手で入れます。`until` の日付を過ぎると自動で無視されます。

```json
{ "games": { "big": { "carryover": 5001651420, "note": "公式サイトで確認した値", "until": "2026-10-20" } } }
```

### くじ別ページの解説を直す

くじ別ページの「〇〇の特徴と還元率」と「〇〇のよくある質問」は、`data/guides.json` に書いています（書いてあるくじのページだけに出ます）。

- `about`：話題ごとのカードです。`type`（`rules`=遊び方・`rate`=還元率・`odds`=当たりやすさ・`buy`=買える場所。色とアイコンが決まります）、`key`（右上に出る要点。20字まで）、`text`（本文）を書きます。本文の `**` で囲んだ部分は、黄色いマーカーの太字になります。キャリーオーバーの額や今日の還元率のように毎日変わる数値は書きません（ページの上の方に自動で出ます）。
- `faq`：質問（`q`、「？」で終わる）と答え（`a`）の組です。検索エンジン向けの「よくある質問」の情報も自動で付きます。
- `sources`：確認に使った公式ページ（ページの「出典」に加わります）。`checkedOn`：確認した日（ページに「〇年〇月〇日に公式の発表で確認」と出ます）。報道にもとづく内容など、公式の発表でまだ確認できていないときは、`note` に注記を書くと、確認日の代わりにその注記が出ます。公式発表から自動で登録・更新したジャンボ（`data/games.json` に `autoFrom` がある項目）は、`note` の代わりに「〇年〇月〇日の宝くじ公式サイトの発表にもとづきます」と出ます（解説を見直したら、`note` を消して `checkedOn` をその日にすると、確認日が出ます）。
- 「必ず当たる」「一番儲かる」のような言い回しは使えません（`node scripts/test.mjs` で止まります）。
- 解説を書いていないジャンボ（自動で登録したものなど）は、賞金表から解説とよくある質問を自動で作ります（遊び方・還元率・当たりやすさ・買える場所）。手で書くと、そちらが使われます。
- 終わったジャンボを `data/games.json` から消したときは、`data/guides.json` の同じIDも消してかまいません（残っていても使われません）。

### 解説ページ（宝くじの基礎知識）を直す・足す

`content/guide/` の `.md` ファイルが、1つずつ `guide/ファイル名.html` のページになります（一覧のページは `guide.html`）。サイドバー・フッター・宝くじ一覧・トップページの下からリンクし、サイトマップにも自動で入ります。

ファイルの先頭の `---` で囲んだ部分が設定です。

| 設定 | 中身 |
|---|---|
| `title` | 検索結果に出る題名（「｜宝くじ還元率ランキング」を足して60字まで） |
| `h1` | ページの見出し（なければ `title`） |
| `short` | サイドバーなどに出る短い名前 |
| `description` | 検索結果に出る説明（160字まで） |
| `checkedOn` | 法令や公式の案内で内容を確かめた日（ページに「内容の確認日」として出ます） |
| `order` | 並び順（小さい順） |
| `sources` | 出典。`- 名前 \| https://…` の形で1行に1つ |

本文の書き方：

- 最初の段落はリード文になります。`## 見出し {#id}` が大見出し（`id` は目次に使うので必ず付けます）、`### 見出し` が小見出しです。
- `**太字**`、`[リンク](kuji/loto6.html)`（サイト内はサイトの一番上からの書き方。トップページは `[トップ](/)`）、`- 箇条書き`、`1. 番号付き`、`| 表 |`（2行目は `|---|---:|`。`---:` は右寄せ）、`> 注意書き`、`!> お知らせ（黄色の枠）` が使えます。
- `Q: 質問？` と `A: 答え` を組にすると、よくある質問になります（検索エンジン向けの情報も自動で付きます）。
- 毎日変わる数字は、手で書かずに自動の数字を使います：`{{rate:loto6}}`（今日の還元率）、`{{ev:loto6}}`（期待値）、`{{price:loto6}}`（1口の値段）、`{{p1:loto6}}`（1等の確率）、`{{max:loto6}}`（還元率の最大値）、`{{name:loto6}}`（くじの名前）、`{{date}}`（今日の日付）。`loto6` の所は `data/games.json` のくじのIDです。
- 1行だけで書くと表などに置き換わるもの：`{{table:ev}}`（還元率と期待値の一覧）、`{{table:chance}}`（当選確率の一覧）、`{{chance:summary}}`（当たりやすいくじ）、`{{chance:years}}`（何年に1回当たるかの目安）、`{{table:gift}}`（贈与税の早見表）、`{{table:shops}}`（購入場所の比較表）、`{{list:jumbo}}`（発売中・発売予定のジャンボ）、`{{list:co}}`（キャリーオーバーが出ているくじ）。
- ページの最後には、のめり込みへの注意と出典が自動で付きます。
- 書き方の誤り（知らない自動の数字・id のない大見出し・閉じていない表など）や、「必ず当たる」「一番儲かる」のような言い回しは、`node scripts/test.mjs` で止まります。原稿で使っているくじが `data/games.json` からなくなったときは、止めずに「—」と表示して、実行の記録に注意を出します。
- 税金・受け取り方・法令など変わり得る内容を直したときは、一次情報（e-Gov法令検索・国税庁・発売元・銀行の公式ページ）で確かめて、`checkedOn` を確かめた日にします。

### 新しいジャンボ宝くじ（自動で登録）

ジャンボは回ごとに賞金表が変わります。毎朝の見張りで、宝くじ公式サイトの[宝ニュース](https://www.takarakuji-official.jp/news/top.html)の「ジャンボ宝くじ等」のお知らせを開き、賞金表（各等の金額と本数）・発売期間・抽せん日・1枚の値段・発売総額を読み取ります。上の検算にすべて通ると、`data/games.json` に自動で足します（例：年末ジャンボミニ2026 → `nenmatsumini2026`）。くじ別ページ・ランキング・宝くじ一覧・購入場所（`config/links.json` の `jumboDefault`＝宝くじ公式サイト・みずほ銀行）も、同じ更新で自動でできます。

1. 登録されると「【確認のお願い】〇〇を自動で登録しました」という Issue が届きます。
2. Issue の「公式の発表」を開き、表の数字・発売期間・抽せん日が同じか見比べます。
3. **同じなら Issue を閉じます**（いちばん下の「Close issue」）。次の朝の更新で、ページの「確認待ち」の注記が消えます（`verify` が消えます）。
4. 違っていたら、閉じずに Issue の内容を Claude に見せて「直して」と頼みます。

そのほかの動き：

- 報道などをもとに手で入れた仮の賞金表（`verify` があり `autoFrom` がない項目。いまの `nenmatsu2026`）は、公式発表が出ると公式の内容に置き換え、同じように確認をお願いします。手で書いた解説（`data/guides.json`）は変えないので、日付や金額が合っているかも見てください（合わない日付は Issue に書きます）。
- 確認待ちの間に公式発表が直されたら、読み直して新しい Issue でお願いします。確認済み（`verify` なし）の項目と公式発表が違うときは、自動では変えずに知らせます。確認待ちの項目を手で直したときも、自動では上書きしません。
- 読み取れなかったとき・検算に通らなかったときは載せずに知らせます。手で足すときは、`halloween2026` などをまねて `data/games.json` に書きます（`salesStart`・`salesEnd`・`drawDate`・`totalTickets`・`tiers` の賞金と本数）。
- 見落とし防止に、宝くじ公式サイトの「現在取扱い中のジャンボ宝くじ等の普通くじ」に出ているのに登録がないジャンボも知らせます。
- 発売が終わったジャンボは、ランキングから外れ、くじ別ページの購入ボタンが消えて「発売は〇月〇日で終わりました」といま買えるジャンボへの案内が出ます。抽せんが終わると、宝くじ一覧とサイドバーからも外れ、宝くじ一覧のいちばん下の「終わったジャンボ宝くじ」にまとまります（ページは残るので、検索から来た人も見られます）。手で消す必要はありません。消したいときは `data/games.json` から項目を消します。
- ジャンボの購入先は、`config/links.json` の `jumboDefault`（宝くじ公式サイト・みずほ銀行）を全部のジャンボに使います。ジャンボごとに変えたいときだけ、`games` に同じIDで書きます。
- ジャンボのくじ別ページには、賞金表から計算した「何枚買うと当たる？（10枚・30枚・100枚で1万円以上・10万円以上・100万円以上・1等が当たる確率と、平均で戻る金額）」と、同じ日に発売・抽せんのジャンボ（ミニなど）との比較を自動で出します。よくある質問にも「何枚買えば1万円以上が当たるか」「どちらが当たりやすいか」を足します（手で書いた解説のジャンボにも足します）。
- ジャンボのページの題名は「年末ジャンボ宝くじ2026の還元率と当たる確率」のように年を付けます（年を付けて探す人が多いため）。トップページには、発売中と45日以内に発売のジャンボを「ジャンボ宝くじ（発売中・発売予定）」として出します。

### 新しいくじ・ルールの変更

- **新しいくじ**：宝くじ公式サイトのメニュー（ネット購入・宝くじ商品のご案内）と、スポーツくじの BIG系・DUNK の「くじ情報」「くじ結果」に、このサイトが知らないくじが出たら Issue で知らせます。数字選択式やスポーツくじの新しいくじは、しくみ（値段・確率・配分・上限）とデータの取り方を決める必要があるので、自動では載せません。載せるときは Issue を Claude に見せて「追加して」と頼みます。
- **ルールの変更**：ロト6・ロト7・ミニロト・ビンゴ5・ナンバーズ4・3の商品紹介と、BIG・DUNK の「くじの種類」のページ（`config/watch.json` の `rule-`）で、1口の値段・賞金・確率・配分・上限が書かれた行が変わったら知らせます。還元率の計算に直接ひびくので、`data/games.json` を直します（Claude に頼めます）。

## 計算の前提

- 還元率は、キャリーオーバー・1口の上限・同じ等級の当せん者との山分け（ポアソン分布で近似）を織り込んだ「1口あたりの平均払戻額」を1口の値段で割ったものです。詳しくはサイトの「計算方法」に書いています。
- BIG の BIG777 の回（毎月7日を含む週の回）は、1等の上限を7億7万7千円にして計算します（上の「BIG777（毎月7日を含む週の BIG）」）。過去の推移も、BIG777 の回は同じように計算し直しています。
- ポイント込みの還元率は、還元率に、そのくじをいちばんポイントが付く買い方で買ったときのポイント還元率（1ポイント＝1円）を足したものです。
- 締切前の回の販売額は分からないため、直近の販売実績の中央値で見積もっています。繰越が大きい回は売上が伸びやすく、実際の還元率は少し下がることがあります。
- 還元率の推移のうち、サイトで記録を始める前の期間は、公式の販売実績額と繰越額から計算し直した値です。
- 前の回の結果が出る前は、直近の確定した繰越額で計算し「暫定」と表示します。
